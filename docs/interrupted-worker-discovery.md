# Auditing interrupted worker discovery

Coterie's retained submission path can submit a clean, independently reviewed
commit after verified worker exit without spending another worker admission.
Discovery must distinguish an implemented tool, the selected role's authority,
and the assignment's current prerequisites. The October 12, 2026 Basin audit
also found a current bridge naming bug: MCP `prime.commands` advertised
`task_submit-retained`, while the callable tool was `task_submit_retained`.
The bridge now normalizes both spaces and hyphens to match its generated tool
names. CLI `prime` retains the command spelling `task submit-retained`.

## Pin the deployment before reproducing discovery

Each new supervisor-owned worker records `launch_contract` in its
`session.started` event. As the operator, retain the event for the exact run,
agent, session, and generation using `coterie events --json`. It records:

- The supervisor version, internal protocol version, and SHA-256 of the Linux
  running executable. An unreadable executable produces null, which remains
  unknown. The hash comes from `/proc/self/exe`, so replacing the installed
  path does not misidentify a supervisor already running.
- The admitted provider's probed name, version, capabilities, and the
  capabilities required for the selected launch.
- The selected role, permission profile, and saved configuration fingerprint.
- The supervisor's compiled bridge catalogue names and SHA-256 of the compact
  JSON tool array generated by the typed Rust definitions.

The event records the admitted contract before launch. It does not prove MCP
initialization, successful provider discovery, or task completion. Separately
retain the authenticated bridge's `initialize` server version and actual
`tools/list` response, and the provider's MCP inventory for that session's
unique server name. Compare the complete discovered catalogue with
[the generated contract](../schemas/mcp-tools-v1.json), including input schemas
and descriptions. The compiled catalogue hash covers the ordered tool array,
without the file's outer `schema_version` wrapper. Record the bridge executable
hash separately if installation changed while the supervisor was running.

Retain `prime.session`, `prime.identity`, and `prime.commands` from that bridge.
The CLI version on PATH, a cached provider inventory, or a catalogue from an
older generation cannot identify the active deployment. Record any missing
evidence as unknown and report the exact server and discovery diagnostic to the
operator. Do not record credentials or complete inherited environments.

## Discover authority and choose the continuation

At startup, discover `Coterie prime` with `tool_search` when tools are deferred.
Then search for the exact required MCP name, such as
`Coterie task_submit_retained`. The common catalogue advertises implemented
tools across roles. MCP `prime.commands` identifies the selected role's
authorized tool names; CLI `prime.commands` uses CLI command spellings.
Catalogue presence never grants authority, and each invocation rechecks the
current session and generation.

An operator or another agent with `task:submit-retained` may submit the exact
reviewed full lowercase commit ID when the active unfinished assignment still
owns its claim. Worker credentials must be revoked, an exit must be recorded,
and a fresh provider check must prove the recorded process exited or is absent
following that exit. HEAD and the owned reference must match the reviewed ID.
The worktree and index must be clean and fully inspectable, with no pending
launch, control, creation, or integration operation. The worker cannot submit
its own assignment this way. Include the independent review and its source,
validation outcomes, blocked checks, and submission reason.

When role authority is missing, ask an authorized coordinator or the operator.
If an authorized tool is missing in the deployment, ask the operator to compare
the recorded contract with actual discovery. Ordinary `task recover` remains
the supported alternative after verified exit: preserve the source, record the
handoff, and start a fresh worktree continuation within saved admission limits.
Dirty work also follows that path. Unknown exits require operator inspection.
The separate operator-only `--acknowledge-lost` path requires a lost session and
a fresh absence proof; process absence alone never becomes an observed exit.

After either submission path, review, integrate, validate the target, and
explicitly close the task. The [review acceptance guide](review-acceptance.md)
applies equally to unchanged worktree reviews: submit the base commit and
request guarded no-op integration before closure. If the target advanced,
mechanical integration does not establish that the reviewer examined that
newer target. Dependencies remain blocked until accepted closure.

## Keep exit diagnostics separate from acceptance

Authorized `poll` and `progress` readers see observed process exit codes,
control reasons such as `execution_timeout`, and current job deadlines. With
log authority, inspect the relevant transcript through terminal EOF and check
`incomplete_tail`. Capacity messages remain attributed provider reports in
the transcript, rather than a guessed process-exit reason. A timeout control
records why Coterie stopped the job, separately from how the process exited.
An exit with no diagnostic retains an unknown cause. A partial diagnostic can
quarantine a session without establishing an exit; it cannot authorize ordinary
recovery or retained submission. Provider exit never submits or accepts a task.

## Verification

[Discovery integration tests](../tests/supervisor_runtime/discovery.rs) compare
the authenticated bridge's complete catalogue with the generated contract,
verify every advertised authorized command is callable by name, and exercise
custom selected roles with and without retained authority. They verify launch
evidence against the actual test executable and provider contract, submit the
reviewed commit through MCP, preserve the original index, reject premature
closure, integrate and validate the target, release dependencies only after
closure, replay submission, and fence revoked callers.

The diagnostic cases replay the recorded capacity frames, an exit without a
reported cause, an execution timeout, and an incomplete diagnostic. They keep
unfinished tasks unaccepted. Existing retained-submission, lost-worker,
deadline, and [review acceptance](review-acceptance.md#regression-coverage) tests
cover exact-commit guards, pending controls, live and unknown process proof,
generation fencing, dirty targets, and unchanged review integration.

```console
cargo test --test supervisor_runtime mcp::discovery::
cargo test --test supervisor_runtime retained::
cargo test --test supervisor_runtime review_acceptance::
cargo test --bin coterie supervisor::bootstrap_tests::
```

Real-provider discovery remains an explicit opt-in in the
[MCP conformance tests](../tests/supervisor_runtime/mcp.rs).
`installed_codex_mcp_routes_authenticated_rpc` checks the installed provider's
complete inventory without a model turn.
`installed_codex_jobs_use_mcp_and_preserve_the_sandbox` asks actual workers to
discover the deferred retained tool and verifies denied authority under their
selected profiles. These tests require local authentication and are excluded
from ordinary CI. Deterministic coverage does not establish the missing
historical provider version or catalogue.

The full `task check` gate passed: formatting, Clippy and actionlint, all 597
ordinary tests, rustdoc, the public site and link checks, dependency audits,
release verification, and Nix evaluation. The 28 skipped tests include explicit
provider opt-ins and artifact regeneration commands. Real-provider opt-ins
were not enabled for this audit.
